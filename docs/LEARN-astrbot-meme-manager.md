# 学习 astrbot_plugin_meme_manager（并落地到 dsh-channel-wechat）

- 对象：[anka-afk/astrbot_plugin_meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager)（v5.3.x，MIT）
- 目的：吸收成熟表情包管理器的工程做法，改进 `dsh-channel-wechat` 的 `/emotion` 表情库。
- 日期：2026-11-15

## 一、它做对了什么

| 能力 | 做法 | 对我们的启发 |
| --- | --- | --- |
| 多表情包 | 包（pack）+ 分类 + 使用规则；默认/会话/人格绑定，多包混用 | 我们单库单目录，暂不需要多包 |
| 智能发送 | 分类级标签让主模型选类；图片级语义检索（描述 + 向量） | 我们是本地关键词打分；语义检索是后续可选方向 |
| 自动收集 | 监听收到图片 → 视觉模型识别分类 → 去重/审核 → 入包；有队列、来源冷却、抽样、每日限额、7 天观察窗口 | 我们目前只在 `/emotion add` 手动收录；采样/冷却值得借鉴 |
| 内容校验 | 默认 JPEG/PNG/GIF/WebP；≤20 MiB、≤4000 万像素；校验真实内容而非扩展名；动图最多抽 5 帧 | 我们补了魔数校验 + 20MB 上限 |
| 去重 | 保存前按内容 SHA-256 去重 | **已落地**：索引加 `sha256`，重复上传不再落盘 |
| 审核 | 自动收集默认进人工审核；分类置信度排序、改分类、丢弃、不再收集 | 我们可直接 `/emotion rename`、`note`、`delete`，暂不做审核队列 |
| 资源广场/图床 | 安装社区包；R2/WebDAV/Fig 等云同步 | 超出当前单机需求，暂不做 |
| WebUI | 分类预览、拖拽、批量移动、更新差异预览 | 我们面板只有功能开关；图库管理页是后续方向 |
| 提示词管理 | 前缀/后缀模板，主模型按分类标签回 `&&meme:分类` | 我们的分类是 25 类固定项，模型只回分类名 |

## 二、本次落地（v2.21.0）

1. **内容 SHA-256 去重**
   - 索引条目新增 `sha256`；
   - `saveEmotionBuffer` 先算哈希，命中已有条目直接返回 `{ duplicate: true }`，不写文件；
   - 上传重复图片时回复「这张已经在「分类」里了，没有重复收录」；
   - 旧图库（无 sha256）在 `/emotion dedupe` 时补齐哈希。
2. **图片内容校验**
   - 按魔数识别 PNG/JPEG/GIF/WebP（不信扩展名）；
   - 超过 20 MiB 拒绝；
   - 非图片直接回复「不是支持的图片」。
3. **`/emotion dedupe`**
   - 扫描全库，按内容哈希保留最早收录的一张，删除重复文件与索引；
   - 顺带清理「索引有、文件没了」的条目；
   - 直接解决之前迁移/手工拷贝留下的 `加油_2…_5` 重复问题。
4. **分类仍由 DSH 模型亲自识别**（2.20.x 已落地）
   - `deepseek-flash` 支持图片输入；`maxTokens` 20.3 修正后识别正常。

## 三、暂不落地 / 后续

- 自动收集（监听聊天图片、抽样、冷却、每日限额、待审桶）：需要视觉模型调用配额与“是否允许收集他人图片”的产品决策，默认关闭更稳妥。
- 语义检索（描述 + 向量）与多包/会话绑定：数据量和场景还不够，先保持 25 分类本地选类。
- WebUI 图库管理（拖拽/批量/预览）：面板可后续加“表情库”页签。
- 云端同步：当前只有本机表情目录，无图床需求。
