# 2.22.0 更新报告（让 Bot 真正发用户给的表情）

- 版本：`2.21.0` → `2.22.0`
- 日期：2026-11-15
- 背景：用户反馈「一直不正常发表情包」，要的效果是发用户自己给的二次元表情（如超时空辉夜姬），而不是默认表情。

## 一、问题

1. 表情库被清空（`index.json` 为空、分类目录全空），没有图可发；
2. 原 `maybeSendEmotions` 只在关键词命中且分类有图时发送：
   - 「超时空辉夜姬」「发表情包测试」这类话不命中 25 类的关键词；
   - 命中分类没图时直接放弃；
   - 冷却 300 秒，连续要求也不发。

## 二、修复

`maybeSendEmotions` 重做：

- **明确请求**：用户文本匹配「发/来/整/要/看/给 … 表情/表情包/二次元」→ 必定发一张（最多 2 张），**不受冷却限制**；
- **随机兜底**：没有命中关键词时，按 `emotionRandomChance`（默认 30%）从所有有图的分类里随机发；
- **分类为空不再放弃**：命中分类没图时从其它有图分类里选；
- 发送成功才更新冷却时间，日志记录 `requested` 标记。

新增导入接口：

```
POST /wechat-channel/emotion-import
{ "path": "C:\\path\\to\\sticker.png", "name": "可选", "category": "可选兜底" }
```

图片会先走模型识别分类，再写入 emotion 库（SHA-256 去重）。

## 三、恢复用户表情

从用户提供的会话 zip 的 `media/` 中恢复用户给的二次元表情（512×512 紫发动漫头像），通过 `emotion-import` 导入；默认表情不再补回。

## 四、验证

- `test-emotion.mjs` 13 项：新增「明确要表情时绕过冷却并发送」；
- 二十三套合计 **148 项通过**。

- `index.js`：发送策略、`emotionRandomChance`、`/emotion-import`、版本号
- `cordis.patch.yml` / `README.md`：新配置
